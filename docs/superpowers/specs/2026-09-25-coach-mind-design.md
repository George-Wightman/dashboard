# The Coach's Mind

Designed 25 September 2026, with George. Sub-project 1 of 4 (the Mind, with notifications). Google
Health (2) and Hebrew both ways (3) get their own specs; this one reserves the hooks they need.

## Why

> I feel like it's good at the moment but it's missing some edge … a sharper, more intelligent
> underlying system that understands and interprets my actions. The coach has a more involved role,
> it's not just waiting for me to reply, it's pinging me "why did that get moved", "I just saw you
> completed the first RP, getting a summary of your progress" … observing what's in my calendar, not
> just the algorithm moving it around, actually reading what's there, reassessing my plan under the
> bonnet. Since this stuff is not facing we can chain API calls — latency isn't an issue, depth is.

What the live data showed on 24 September:

- The evening opener went out at 18:00 asking how the role plays went. Both were ticked at 19:23 —
  by Claude, from the session in which George did them — and the Coach never noticed. It speaks on a
  timetable (three openers, generated by whichever page is open) and reacts to nothing.
- Each turn is one call to Gemini flash-lite with ~14,000 characters rebuilt from scratch. Nothing
  carries an understanding of George from one week to the next.
- It never sees content: calendar events arrive as titles; `RP2_debrief.md` and `RP3_debrief.md`
  sit in Drive, unread.
- Attention held eight "couldn't fit → moved" lines for the AC fortnight; nothing asked whether the
  plan still fits before 5 October.

## Decisions (George)

| Question | Decision |
| --- | --- |
| What pays for the thinking | **Nothing extra.** No Anthropic API. Gemini's free tier does as much as it can (it may run chains and parallel calls — "we can let loose a little"); Claude, on his subscription, does the deep runs through a Claude Code cloud routine. |
| How pings reach him | **Web push from the installed Today app** (phone and laptop; the Pixel Watch mirrors the phone). |
| What Gemini may see | Calendar descriptions and Drive files, yes. **Health only as plain labels** ("short night", "35-min walk"); raw numbers and trends go to Claude only. |
| What the Mind may change | **Proposals only.** Every unprompted plan change waits for his Apply. Sensor facts (a walk from the watch, later) are recorded directly. |
| Shape | **A: in the cloud** — the planner senses and pings, Gemini reacts, a Claude routine thinks deeply. Works with the laptop shut. |

## Rules that hold it together

1. **The background speaks first; the page answers.** Every message George didn't prompt is written
   by the planner (Gemini) or the routine (Claude) — never by whichever device is open. The page's
   own opener generation becomes a fallback for when the background is down.
2. **Facts before opinions.** Senses are plain code. The AI interprets; before anything is said,
   code and a critic pass check it against ticks and bookings.
3. **Proposals, not edits** (above).
4. **Hard caps on what reaches him**, generous caps on thinking: at most 6 pings and 8 unprompted
   Mind messages a day, a 45-minute gap between unprompted messages unless one is urgent, silence
   from bedtime to morning. Gemini calls are capped at 120 a day (quota errors back off for the day).
   Claude: 2 scheduled runs plus at most 3 triggered a day (Pro allows 5 routine runs).
5. **The Mind's memory lives outside the synced file.** `mind.json` beside `data.json` in
   `dashboard-sync` holds the event stream, run log and push ledger. `data.json` (1.1 MB, pulled whole
   by every device and every planner run) only gains what devices show: messages, proposals, a
   picture of George of at most 4 KB, push subscriptions and a status line.

## Architecture

```
 Your lists · Calendar · Drive files · (watch, Hebrew later)
                         │
                   Senses (planner, every 10 min, plain code) ──► mind.json events
                     │                         │
            Reflexes (Gemini, in the     Deep mind (Claude routine: 06:30, 21:30,
            planner, minutes)  ─escalate─►  and up to 3 fired by the planner)
                     │                         │
                     └────► Coach conversation ◄┘ (messages, proposals, the picture)
                                   │
                        planner sends Web Push ──► phone, laptop, watch
```

### Where each piece runs

| Piece | Runs in | Code |
| --- | --- | --- |
| Senses | Apps Script planner, inside `run()`, after the calendar is written | `planner/senses.js` (pure), `planner/drive.js` |
| Reflexes, openers | Apps Script planner, same run, bounded | `planner/reflex.js` (pure, Gemini injected), `planner/gemini-gas.js` |
| Push | Apps Script planner, end of run | `planner/push.js`, `planner/p256.js`, `planner/aes.js` |
| Mind state | Shared | `js/mind.js` (data.json records, checks, pure), `js/mind-state.js` (mind.json shape and merge, pure) |
| Deep mind | Claude Code cloud routine, running the dashboard tool from the public repo | `claude/mind.js` (the `mind` read and mind-mode ops), `claude/mind/ROUTINE.md` |
| Voice | The page | `js/talk.js`, `js/coach-tools.js`, `js/ui/coach.js`, `js/push-client.js`, `sw.js` |

The Mind's work in `run()` is wrapped like goal reviews: a failure is logged in its status and
never stops planning. It starts after the calendar has been written, and stops starting Gemini
chains once the run has used 150 seconds (Apps Script allows 6 minutes a run and ~90 a day in
total; the planner's own share is measured and shown — see Limits).

## Records

### In `data.json` (all in maps old devices already accept)

A new record *kind* would make every device still on old code reject the whole document during sync,
so everything new lives in the `calendar` map (generic records) or reuses `talk`:

| Record | Shape | Written by |
| --- | --- | --- |
| `calendar['mind:config']` | `{ enabled, morningAt: '07:00', checkinAt: '18:00', quietFrom: '22:30', quietUntil: '07:00', pingsPerDay: 6, messagesPerDay: 8, gapMinutes: 45, geminiPerDay: 120, deepPerDay: 3, models: { think, check } }` | Claude (`mind` op); defaults in `js/mind.js` |
| `calendar['mind:status']` | `{ lastRun, lastReflex, lastDeep, lastError, today: { day, gemini, messages, pings, deep, runMs } }` — a heartbeat at most every 55 minutes (as the planner's own status), sooner when something in it changed | planner, tool |
| `calendar['mind:picture']` | `{ text (≤ 4,000 chars), opener: { day, text } | null, by: 'claude', at }` | deep runs only |
| `calendar['push-config']` | `{ publicKey }` (VAPID, base64url) | planner, once |
| `calendar['push:<device>']` | `{ endpoint, p256dh, auth, label: 'phone'|'laptop', at }`; archived when the push service says it's gone | the page; planner archives |
| `calendar['ask:<id>']` | `{ text, day, at }`; archived once taken | the page (the Coach's `think_deeper`) |
| `journal['talk:<day>:mind-<n>']` | an ordinary talk, slot `mind-<n>`, opened by a Reflex | planner |
| `journal['talk:<day>:deep-<n>']` | an ordinary talk, slot `deep-<n>`, opened by a deep run; may carry `proposal` | tool |

Mind messages are ordinary `{ who: 'coach', text, at }` messages with four extra fields old code
ignores: `from: 'mind'`, `by: 'gemini' | 'claude'`, `notify: true|false`, and `ref: [eventIds]`.
Reflex and deep talks use different slot prefixes so the planner and a deep run writing at the same
moment never share a record (a shared `proposal` field would be last-writer-wins). The slot pattern
in `js/data.js` grows to `mind-\d{1,3}` and `deep-\d{1,2}`; `recordProblem` never checked slots, so
old devices accept them.

### `mind.json`

```js
{
  schema: 1,
  cursor: { at, items: { id: 'status|date|time' }, done: { logId: status }, talks: { id: count },
            events: { calendarEventId: 'updated' }, flags: [ids], milestones: { id: done } },
  events: { [id]: { id, at, kind, level, by, refs: {...}, text, facts: [...], artefacts: [...],
                    health: { label, detail } | undefined, reflex: at | null, deep: at | null } },
  runs:   { [id]: { id, at, engine: 'reflex'|'opener'|'deep', trigger, events: [ids], calls, said, summary, error } },
  pushed: { [messageKey]: at },
  fired:  [ { at, reason, events: [ids] } ],
  budget: { day, gemini, messages, pings, deep, lastSaid, geminiBlocked }
}
```

- Written by the planner every run in which something changed, and by the tool at the end of a
  deep run. Conflicts are the usual sha retry; `mergeMind` unions events and runs by id, takes the
  later `reflex`/`deep` stamp per event, the union of `pushed`, the larger counters for the same
  `day`, and the planner's cursor (the tool never writes it).
- Events and runs older than 14 days are dropped; artefacts are capped at 12,000 characters per
  event and events keep at most 300.
- A missing or unreadable `mind.json` starts empty, and **a run with no cursor records a baseline
  and no events**, so a reset can never flood George with the past.

## Senses

`sense({ doc, before: cursor, events: calendarEvents, now, dayStartHour })` → `{ cursor, events }`.
Pure. It compares the document and the calendar with the cursor, attributes each change, and scores
it. Attribution comes from `doc.changes` (source `calendar` = George in Google Calendar, `coach`,
`claude`, `workflow`) and from the log's own `source` (`me`, `claude`, `hevy`, `hebrew`, `coach`);
an item change with no change record is George in the app.

| Event | When | Level |
| --- | --- | --- |
| `tick` | a done log appears for a task or habit | 3 for a task in a goal due within 21 days, a starred task, or one whose notes name a Drive path; 2 for another goal task; 1 otherwise |
| `untick` | a done log is archived | 1 |
| `pushed` | a task committed today (`commit:<day>`) now has a later `date`, not by the planner | 3 |
| `dropped` | a committed task archived | 3 |
| `moved` | George dragged or retimed a block (change source `calendar`) | 3 if it changed day or left today, 2 within the day |
| `slipped` | a block ended ≥ 30 minutes ago with its items unticked (once per item per day) | 2 (3 if starred or ≥ 2 items) |
| `overflow` | a task newly booked on a later day than asked, by the planner | 1 each; the set decides plan risk (below) |
| `calendar` | an event not made by the planner appears, changes time, or goes, today to +7 days | 3 if today or tomorrow and it overlaps a booked block; 2 today/tomorrow otherwise; 1 later |
| `milestone` | a milestone turns done | 2 |
| `workout` | a Hevy workout ticks Gym | 1 (his training is his own) |
| `hebrew` | the Hebrew logs change | 1; 2 when a Hebrew target is behind with ≤ 2 days left |
| `reply` | George answers a Mind message | 1 (read by the next deep run; the Voice already answered) |
| `ask` | an `ask:` record | deep run |
| `flag` | a new flag | 1 |

Calendar events carry title, calendar, start, end, all-day and the description clipped to 600
characters. The planner already fetches them in full each run; only titles reach `data.json`, as now.

**Artefacts.** When a task whose notes contain a Drive path (`Job Search/IDADP/Practice/...`) is
ticked, `planner/drive.js` resolves the folder from My Drive's root and reads the text files there
and one level up (`.md`, `.txt`; `.html` stripped to text) modified in the last 3 days, newest first,
to 12,000 characters. That is what turns "RP ticked" into a reading of `RP3_debrief.md` and
`reflections.md`. It needs the `drive.readonly` scope.

**Plan risk** (deterministic): three or more `overflow` events for tasks of one goal within a day,
or any task of a goal pushed past the goal's target date, raises one `risk` event (level 3,
escalate) per goal per day.

## Reflexes (Gemini)

Each run, after sensing, the planner picks the unhandled events at level 3, and at level 2 once
they are 20 minutes old (so a burst of ticks is one message, not five). It groups them by subject
(an item and its goal; a calendar change; a slip) and runs at most two chains per run.

A chain (all calls JSON mode, `planner/gemini-gas.js`, parallel with `UrlFetchApp.fetchAll`):

1. **Read** (parallel, `models.think`, default `gemini-flash-latest`): up to three angles, chosen by
   event kind — *progress* (the goal, its milestones and deadline, what the artefacts say, how it
   compares with the last one), *pattern* (the picture, recent journal, earlier events of the same
   kind), *plan* (today's and tomorrow's shape, what's committed, what moved). Each returns
   `{ notes, matters: 0-3 }`.
2. **Draft** (`think`): from the angles, the picture and the rules — `{ say: bool, text, question,
   notify: bool, escalate: bool, why }`. It must name specifics and end in at most one question.
3. **Check**: plain-code checks (below) and a critic call (`models.check`, default
   `gemini-flash-lite-latest`) given the facts list and the draft — `{ ok, problems, text }`. One
   revision; a draft still failing is dropped and logged.

Output: a message in a new `mind-<n>` talk (`by: 'gemini'`), `notify` if the draft asked for it and
the event was level 3, within caps; `escalate` records a fire request. Every handled event gets its
`reflex` stamp whether or not anything was said.

**What Gemini is given**: event facts, the item/goal/milestones, today's and tomorrow's lists
(`listText`), `commitmentLines`, `dayShape`, the picture, recent Mind messages (to avoid repeating),
calendar descriptions and artefacts. **Never**: `health.detail` (only `health.label`), keys,
subscriptions. A test enforces this on every prompt builder.

**Plain-code checks** (`checkMessage` in `js/mind.js`, used by Reflexes and the tool):

- no claim that something was done ("done", "ticked", "finished", "completed", "nailed", "got
  through") next to the title of an item that isn't ticked today;
- every clock time mentioned is a booking, a calendar event, or a time George wrote himself today;
- a times-a-week habit that is optional today is never called a miss;
- at most 600 characters, no emoji, not a near-repeat (word overlap > 0.6) of the last five Mind
  messages.

### Openers

The planner writes the morning and evening openers into the same `morning` and `evening` talk ids
the page uses now, so everything that reads them keeps working:

- **Morning**, first run at or after `morningAt` (07:00) and outside quiet hours: the picture's
  `opener` if it's for today and passes the checks, otherwise a Gemini chain (the same prompt the
  page used, plus the picture). Notified.
- **Evening**, first run after `checkinAt` (18:00): a Gemini chain that names what was ticked and
  asks about anything pushed, dropped or missed (`commitmentLines`). Notified.
- The afternoon opener goes: slips are Reflexes now.

The page stops generating openers while the background is alive — `mind:config.enabled` and a
`mind:status.lastRun` under 75 minutes old (the heartbeat is 55). Otherwise it behaves exactly as
today.

## Deep mind (Claude)

A Claude Code cloud routine on George's account, repository `George-Wightman/dashboard`, model
chosen in the routine, Google Drive connector only (read-only by instruction; no Calendar connector —
the planner supplies the calendar, and the calendar playbook's "never touch his calendar" stands).

Triggers:

- **Scheduled** at 06:30 and 21:30 London (cron `30 6,21 * * *`).
- **Fired by the planner** (`POST …/fire` with `MIND_ROUTINE_URL` and `MIND_ROUTINE_TOKEN` from script
  properties) for: an `ask` (one of the three a day is kept for asks); a Reflex's `escalate`; a
  `risk` event. Never while a fire is outstanding (40 minutes, or until a deep run is recorded), never
  in quiet hours except for an ask, and at most `deepPerDay`. The fire text only names the reason
  and event ids; the routine reads everything from the repo.

The routine's saved prompt is two sentences pointing at `claude/mind/ROUTINE.md`, so its behaviour
ships with the code. The run:

1. `node claude/dash.mjs --config env mind` — the context pack: now; the picture; config, budget and
   status; the events since the last deep run (with facts and artefacts, health in full); today and
   tomorrow (`listText`, `commitmentLines`, `dayShape`); the week as booked; goals with milestones and
   deadlines; attention; countdowns; the last three days of conversations in full and the journal;
   last week's digest; open flags; the gym summary; the Hebrew summary.
2. Reads any Drive file it needs (read-only).
3. Thinks. Its brief: understand what happened, update the picture, decide what (if anything) is
   worth saying, reassess the plan against deadlines, and hold George to what he committed to
   (`feedback_hold-him-to-the-day`).
4. `node claude/dash.mjs --config env apply --mind` with at most: one `picture`, two `say`, one
   `propose`, a `brief` for today or tomorrow, a `guide` (Sunday 21:30 / Monday 06:30), `flag` or
   `handoff` for bugs, and exactly one `handled` carrying a one-paragraph summary.

`--config env` reads `DASHBOARD_TOKEN` and `DASHBOARD_REPO` from the environment (a routine has no
config file). `--mind` refuses every other op — a guard against a wrong turn, not a security
boundary (the token can do anything the tool can).

**Mind-mode ops** (`claude/mind.js`):

| Op | Does |
| --- | --- |
| `picture` | `{ text, opener? }` — replaces `mind:picture` (text ≤ 4,000 chars; opener `{ day, text }`) |
| `say` | `{ text, notify?, ref? }` — a message in a new `deep-<n>` talk, after `checkMessage` |
| `propose` | `{ text, ops: [...] }` — runs plan ops (`task`, `edit`, `archive`) on a copy, stores the sparse before/after as that talk's `proposal`, exactly the shape the Coach's proposals use; nothing in the plan changes until George presses Apply |
| `brief`, `guide`, `flag`, `handoff` | as today |
| `handled` | `{ events: [ids] | 'all', summary }` — stamps events `deep`, writes the run record and `mind:status.lastDeep` |

### The picture

Claude's standing understanding of George, rewritten by every deep run, ≤ 4,000 characters, in five
short sections: **Now** (season, what matters this week), **Patterns** (each with the dates that show
it), **Risks**, **Open threads** (questions asked, promises he made in chat), **How to talk to him**.
The Voice and every Reflex read it; only deep runs write it.

## The Voice (the page)

- **Context**: `talkContext` gains the picture (clipped to 3,000 characters, with its age) and the
  last three unanswered Mind messages. `TALK_SYSTEM` gains: messages marked as the Coach's background
  mind are its own and are continued naturally; when George asks for something that needs real
  thought — a re-plan, how something is going across weeks — call `think_deeper` and say it will come
  back to him.
- **`think_deeper({ question })`**: writes an `ask:` record and replies that the answer comes in a
  while (the deep run is fired within 10 minutes, runs for a few minutes, and its message is pinged).
- **The conversation**: `mind-*` and `deep-*` talks show in the stream like any talk George spoke in,
  and are in the model's contents. A Mind message carries a small mark — Gemini's star or Claude's
  spark from `js/ui/sources.js` — with the words only on hover (`feedback_icons-over-text`). Proposals
  render and apply exactly as now. A reply goes into the talk it answers.
- **`waitingOpener`** (the Coach's question under the date on a phone) also shows the latest
  unanswered Mind message of today.
- **⚙ → Notifications**: one line, per device: *Off · Turn on* / *On (this phone)*. Turning on asks
  the browser's permission, subscribes with `push-config.publicKey`, and writes `push:<device>`.
- **⚙ → Claude**: a line saying when the Mind last reacted and last reviewed, and any error.

## Notifications (Web Push)

- The planner makes its VAPID key pair on first use: the private key in script property
  `VAPID_PRIVATE`, the public key in `push-config`. Randomness comes from `Utilities.getUuid()`
  (Java's SecureRandom) hashed with SHA-256.
- Each Mind message with `notify` that isn't in `pushed` is sent to every active subscription:
  payload `{ title: 'Coach', body (≤ 140 chars), url: './?coach=<talkId>', tag: talkId }`, encrypted
  per RFC 8291 (`aes128gcm`, ECDH P-256, HKDF-SHA-256), authorised per RFC 8292 (ES256 JWT, 12-hour
  expiry), `TTL: 43200`, `Urgency: normal`. 404 or 410 archives the subscription; other failures are
  retried on the next two runs, then given up.
- Apps Script has no ECDSA, ECDH or AES, so `planner/p256.js` (BigInt, Jacobian coordinates) and
  `planner/aes.js` (AES-128, GCM) implement them; SHA-256 and HMAC come from `Utilities`. Every
  primitive is tested against Node's `crypto`, and the whole message against RFC 8291's own example.
- `sw.js` gains `push` (show the notification) and `notificationclick` (focus or open the app at
  `?coach=<talkId>`, which opens the Coach at that conversation).
- Pings are suppressed in quiet hours (22:30–07:00, or from `close_day` until morning) and during
  time off that covers everything. The message still lands in the Coach.

## Limits and failure

| What | Behaviour |
| --- | --- |
| Gemini quota (429) | back off for the day (`geminiBlocked`); unhandled events fold into the next deep run |
| A draft fails its checks twice | dropped; the run is logged with the problems |
| Routine fire fails | logged in `mind:status`; the 06:30/21:30 runs still pick the events up |
| A deep run fails part way | `apply` is all or nothing; nothing lands; the routine's session shows why |
| `mind.json` unreadable | start empty with a baseline cursor (no flood) |
| Planner run time | the Mind stops starting chains at 150 s; each run's duration and the day's total go in `mind:status` so the 90-minute daily Apps Script allowance can be watched |
| Background silent > 75 min | the page generates openers again, as now |

## Testing

Node tests, no live calls, following the existing fakes (`tests/planner-apps.js`, `dev/fake-gemini.js`):
senses and attribution; levels, grouping and delays; caps, quiet hours and gaps; `mergeMind`; the
checks; each prompt builder's privacy (no `health.detail`, no keys); the Reflex chain with a fake
`fetchAll` (parallel calls, a critic rejection and one revision, quota back-off); openers and the
page's fallback; P-256, ECDSA, ECDH, HKDF, AES-GCM against `node:crypto`, VAPID JWTs verified by
`node:crypto`, and RFC 8291's example decrypting; push sending and subscription clean-up; the tool's
`mind` read, each mind-mode op, the `--mind` refusals and `--config env`; the page showing Mind
talks with their mark, `think_deeper`, the Notifications line; `sw.js` push and click handlers.

Then against George's real data: replay the Senses over two historical versions of `data.json` from
`dashboard-sync`'s history (24 September, 17:00 → 19:30) and check they produce the two role-play
ticks with their debriefs; run the deep mind's context pack and a dry run of `apply --mind` via
`preview`; and after deployment, watch `mind:status` and `mind.json` for a day.

## Setup only George can do

1. A Gemini key from a new Google Cloud project (so the Mind never shares the Hebrew app's free
   allowance) in the planner's script properties as `GEMINI_KEY`.
2. Paste the new `appsscript.json` (adds `drive.readonly`), run `install`, approve.
3. Create a fine-grained GitHub token for `dashboard-sync` (Contents read and write) and add it to the
   routine's cloud environment as `DASHBOARD_TOKEN`, with `DASHBOARD_REPO=George-Wightman/dashboard-sync`.
4. In the routine, add an API trigger, generate its token, and put the URL and token in the planner's
   script properties as `MIND_ROUTINE_URL` and `MIND_ROUTINE_TOKEN`.
5. ⚙ → Notifications → Turn on, on the phone and the laptop.

Claude creates the routine itself (`/schedule`) and switches the Mind on (`mind:config.enabled`) once
the first planner run with the new code has written a baseline.
