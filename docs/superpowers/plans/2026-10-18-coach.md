# Coach (Build 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude writes George's training sessions onto dated gym tasks. The planner pushes each one
into Hevy as a routine and ticks the task when a workout from that routine is saved. The app asks
the morning back question, shows the session, warns about loaded hinges on sore mornings, and marks
lifts ready to add weight. Claude reads all of it when planning.

**Architecture:**
- **Pure logic:** `js/coach.js` holds the session text, validating a session against Hevy's exercise
  templates, building the Hevy routine payload, the back flag and the ready marks.
- **Where things are stored:**
  - A session is an item field `session` on a dated task (not `details`, whose schema is strict).
  - Its readable text also goes into the task's `notes`, so it reaches the calendar event's
    description through the existing path, with no planner change.
  - Back answers are `gym` records `back:<day>`. The journal's kinds are whitelisted, and older app
    copies would reject a new one.
- **The planner's routine sync:** `planner/routines.js` keeps a small pool of routines in a Hevy
  folder called "Dashboard". Hevy's API has no delete, so a routine whose session has passed is
  reused for the next one.
- **The routine tick:** workouts keep their `routine_id`. A workout from a session's routine ticks
  that task.

**Tech Stack:** Plain ES modules, Node 24 tests, the Hevy public API (Pro): `POST /v1/routines`,
`PUT /v1/routines/{id}`, `GET`/`POST /v1/routine_folders`, with routine body
`{ routine: { title, folder_id, notes, exercises: [{ exercise_template_id, rest_seconds, notes, sets: [{ type, weight_kg, reps, rep_range }] }] } }`.

**Spec:** `docs/superpowers/specs/2026-10-18-daylight-health-design.md`, "Build 4: Coach".
Rulebook: the 17 Oct health report (in the spec's "Decisions already made").

## Global Constraints

- Claude plans; the app and the planner only show the plan, sync it and run fixed rules. No AI in the
  app.
- **Hevy writing is routines only, in the "Dashboard" folder.** Never workouts, never his own routines.
  `HEVY_KEY` stays in the planner script.
- **Session shape:**
  `{ name, note?, exercises: [{ name, sets, reps | repRange: [lo, hi], kg?, rpe?, each?, restSec?, note? }], cardio?: { kind, minutes, hr?: [lo, hi] } }`.
  - `sets` is 1–10, reps 1–50, kg ≥ 0, rpe 5–10.
  - Exercise names must match a Hevy template title (case-insensitive, exact).
- **Session text, one line each:** `Back squat 3×5 @ 95 kg`, `Trap Bar Deadlift 3×6 @ RPE 7`,
  `Bulgarian Split Squat 3×8 each @ 16 kg`, `Bike 25 min, 118–138 bpm`; the note first if there is one.
- **Back question:** fine 0, stiff 1, sore 2, bad 3. Asked from the day's start until 11:00, only on
  days without an answer.
- **Back flag:** a score of 2 or 3 on a day whose session has a hinge (a name containing "deadlift",
  "good morning", "romanian" or "rdl") or a squat at RPE ≥ 8 or at ≥ 85% of his e1RM. Note: "Back's
  sore: swap the deadlift for back extensions, or drop the load." Two scores of 2 or more on
  consecutive mornings add one For Claude flag.
- **Ready to add weight:** every prescribed set of an exercise done at or above its reps (the top of
  `repRange`) at the prescribed kg.
- **Recovery verdict:** deferred to Build 2, since it needs watch data.

## Review Focus

1. **A session whose exercise isn't a Hevy template.** The `session` op refuses it and names the
   closest titles. A template renamed later puts a sentence in the routine status rather than
   breaking the planner (Tasks 1 and 4).
2. **Hevy down or the key refused.** The routines are left as they are, the planner goes on, and the
   status says so (Task 4).
3. **A session task moved to another day or archived.** Its routine follows (retitled), or goes back
   to the pool (Task 4).
4. **A workout not started from the routine** still ticks the Gym habit as before and doesn't tick
   the session (Task 4).
5. **A back answer on the phone and the laptop.** Same id, so they merge to one (Task 2).

### Task 1: Coach logic (`js/coach.js`)

**Produces:**
- `sessionLines(session) -> string[]`
- `sessionText(session) -> string`: the lines joined with `\n`.
- `checkSession(session, templates) -> { exercises: [{ ...ex, templateId }] }`: `templates` is the
  `gym` map's `templates.list` (`{ id: [title, type, muscle] }`). Throws a sentence. An unknown name
  lists up to 3 closest titles (by shared words).
- `routineBody(session, resolved, { title, folderId }) -> { routine: {...} }`:
  - sets are type `normal`;
  - `weight_kg` is `kg` or null;
  - `reps`, or `rep_range { start, end }` with `reps: null`;
  - exercise notes join `RPE n`, `each side` and the exercise note;
  - routine notes are the session note plus the cardio line.
- `isHinge(name)`
- `backFlag(session, score, e1rmOf: (name) => number|null) -> string|null`
- `readyMarks(session, workout) -> string[]`: names of exercises ready to add weight.
  `workout.exercises[].sets` hold `{ kg, reps }`, as `js/gym.js` keeps them.

- [ ] **Failing tests (`tests/coach.test.js`):**
  - session lines for every kind of exercise and the cardio line;
  - `checkSession` resolves names case-insensitively and refuses unknown names with suggestions;
  - `routineBody` matches Hevy's shape exactly;
  - back flag triggers on a hinge or a heavy squat and not on a light day, and needs a score ≥ 2;
  - ready marks for all sets hit, not for one missed.
- [ ] **Implement it; `npm test`; commit:** "Coach: the logic — session text, Hevy routine shape, back flag, ready marks"

### Task 4: The planner pushes routines and ticks sessions

**`planner/routines.js`:** `syncRoutines({ fetch, key, store, now, dayStartHour })`, run after `syncHevy`.
- **The folder:** found by title "Dashboard" (`GET /v1/routine_folders`), else created. Its id is kept
  in the `gym` record `routines` as `folderId`.
- **Sessions:** active tasks with `session`, `date` from today to today + 6, not done.
- **The pool:** `routines.byRoutine: { routineId: { taskId, day, hash } }`. A session without a routine
  takes one whose day is in the past, or whose task is gone, done or archived; otherwise it `POST`s a
  new one.
  - A routine is `PUT` when its hash (session plus day plus title) changed.
  - The title is `<name> · <Wkd> <d Mon>`.
- **Errors:** kept as `routines.lastError` (a sentence, the key scrubbed). Never thrown.
- **The tick:** in `planner/hevy.js`'s reconcile, a workout whose `routineId` maps to a task in
  `byRoutine` ticks that task with `hevy-session-<hevyId>`, the same way the Gym habit is ticked,
  following edits and deletes.
- **`planner/gas.js`** calls `syncRoutines` after `hevy(store)` when `HEVY_KEY` is set, at most every
  10 minutes.

- [ ] **Failing tests (`tests/routines.test.js`, fake Hevy):**
  - folder found or created;
  - a new routine POSTed with the exact body;
  - unchanged means no write;
  - a changed session means a PUT;
  - a passed session's routine is reused for the next;
  - an unknown template means a status sentence, not a throw;
  - Hevy 401 means a status sentence;
  - the routine tick on a matching `routine_id`, and no tick otherwise.
- [ ] **Implement it; `npm run build`; `npm test`; commit:** "Coach: the planner puts sessions into Hevy as routines and ticks them"
