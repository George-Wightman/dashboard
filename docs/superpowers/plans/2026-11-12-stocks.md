# Stocks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Stocks tile and big view that checks each holding against George's thesis through five number lenses, fed by the planner (free numbers) and a capped morning Claude routine (brief, notes, shortlist, one push at most).

**Architecture:** The planner (Apps Script, every 10 min) fetches Trading 212 positions and free prices/accounts once each morning, computes lenses, and writes `stocks/market.json` in the sync repo. Claude (chats and the scheduled routine) owns `stocks/desk.json` (theses, themes, tiers, brief, notes, shortlist, alert, run log) through `stocks` / `stocks-write`. The app reads both files with `refreshFile`, joins them in a pure view-model (`js/stocks.js`) and renders a tile and big view (`js/ui/stocks.js`). Two files instead of the spec's one file with sections, so the planner and Claude can never overwrite each other.

**Tech Stack:** Vanilla ES modules, `node --test`, Google Apps Script planner (bundled by `planner/build.mjs`), the dashboard skill CLI (`claude/cli.js`, built by `claude/build-skill.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-12-stocks-design.md`

## Global Constraints

- Public repo: no real holdings, quantities, values, theses or keys in code, tests, fixtures or docs. Fixtures use invented tickers' data (real tickers are fine as symbols, numbers must be invented).
- No buy/sell advice anywhere in copy: "a moment to add?" questions, never orders; never how much to invest.
- Trading 212 key: Portfolio permission only. George enters `T212_KEY` (and `T212_SECRET` if issued) in Script Properties himself. Claude never types or reads it.
- SEC requests carry a User-Agent from Script Property `SEC_CONTACT`, which George sets himself; with it unset, the planner skips SEC and those lenses go grey.
- No paid APIs; no social sentiment.
- Caps: ≤ 8 searches on a weekday run, ≤ 15 on the weekly run; ≤ 3 What happened, ≤ 3 Coming up, ≤ 2 Worth a look; ≤ 1 alert a day; ≤ 5 kept notes per subject.
- Browser storage: one cached copy of each stocks file only; no price history on the device.
- Phone first: big view works at 380 px with no horizontal scroll; touch targets ≥ 44 px; light and dark. Theme state is a colour dot, never a weather icon. Claude's notes carry the Claude logo with the date, words on hover.
- Any change to a `sw.js` SHELL file ships with `npm run build-release` in the same commit. Planner changes ship with `npm run build-planner`; skill changes with `npm run build-skill`.
- Text files are written with LF line endings.

## Data shapes (shared by every task)

`stocks/market.json` (planner writes; `validMarket`):
```
{ v: 1, at: ISO,
  positions: { at: ISO, error: string|null,
    list: [{ t212: 'NVDA_US_EQ', qty, avg, price, ccy, valueGbp, returnGbp }] },
  account: { valueGbp, returnGbp, dayMoveGbp, dayMovePct },
  lenses: { [ticker]: { trend, price, health, risk: { dot: 'green'|'amber'|'red'|'grey', reason },
            rsi: number|null, sigma: number, moveToday: number, close: number, at: ISO } },
  quotes: { [ticker]: { close, ccy, at } } }      // shortlist tickers too
```
`stocks/desk.json` (Claude writes; `validDesk`):
```
{ v: 1,
  symbols: { [t212]: { ticker, yahoo, stooq, cik: string|null, name } },
  tiers:   { [ticker]: 'watched'|'fund'|'market'|'pie' },
  themes:  [{ id, name, holdings: [ticker], also: [ticker], interests: [string] }],
  theses:  { [ticker]: { line, watch: [string], intact: boolean } },
  lensNotes: { [ticker]: { price?, health?, expectations?: { dot, reason, at } } },
  events:  [{ day, ticker: string|null, theme: string|null, kind: 'results'|'exdiv'|'policy'|'other', text }],
  brief:   { at, verdict, happened: [Item], coming: [Item], look: [Look], payday: { text }|null } | null,
  notes:   [{ at, subject: 'NVDA'|'theme:ai'|'idea:KOG', kind: 'looked'|'thinking'|'next', text, due: day|null, closed: boolean }],
  shortlist: [{ ticker, name, theme, day, price, ccy, reason, status: 'watching'|'dropped', why: string|null }],
  insider: { [ticker]: { at, text } },
  alert:   { id, text, ticker: string|null } | null,
  meta:    { runs: [{ at, kind: 'daily'|'weekly', searches, looked: [subject], skipped: [subject], tokens: number|null }] } }
Item = { text, ticker: string|null, url: string|null, day: day|null }
Look = { kind: 'add'|'idea'|'theme', text, ticker: string|null, url: string|null }
```

## Review Focus

- Trading 212 down or the key missing: the tile shows the last holdings with "as of <day>", one line saying positions couldn't be read, and nothing else breaks.
- A holding in `market.json` that `desk.json` has no tier/symbol for (new buy): shown under "Not sorted yet" as a Pie-like row, and the next `brief-input` lists it as a trigger "new holding: needs a tier and thesis".
- A price source answering 429/empty for one symbol: that symbol's price lenses go grey with "no price data today"; the others are unaffected.
- `desk.json` absent (before the seed) or malformed: the tile still shows value and day move from `market.json` and a line "No brief yet".
- The same alert id seen on two planner runs, or an alert set on a day one was already sent: only one push ever goes out per id, and at most one per day.

### Task 2: The view-model (`js/stocks.js`)

**Files:** Create `js/stocks.js`, `tests/stocks.test.js`, `tests/fixtures/stocks-market.json`, `tests/fixtures/stocks-desk.json` (invented numbers).

**Interfaces (produces):**
- `MARKET_PATH = 'stocks/market.json'`, `DESK_PATH = 'stocks/desk.json'`, `MARKET_KEY = 'dash_stocks_market'`, `DESK_KEY = 'dash_stocks_desk'`.
- `validMarket(x) → boolean`, `validDesk(x) → boolean` (shape checks per Data shapes; `v === 1`).
- `lensesFor(ticker, market, desk) → { trend, price, health, expectations, risk }`: planner lenses, overridden by `desk.lensNotes[ticker]` where present; tiers `fund`/`market` give grey price/health/expectations with reason "doesn't apply to a fund".
- `verdict(lenses, tier) → 'agrees'|'mixed'|'disagrees'|null` — watched: ≥ 4 green and 0 red → agrees; ≥ 2 red, or trend and expectations both red → disagrees; else mixed. fund/market: trend and risk both green → agrees; both red → disagrees; else mixed. pie → null.
- `themeDot(verdicts: string[]) → 'green'|'amber'|'red'|'grey'` — more than half agrees → green; more than half disagrees → red; empty → grey; else amber. A theme uses its watched holdings' verdicts, or its funds' when it has no watched holdings.
- `momentToAdd(ticker, lenses, desk) → boolean` — `theses[ticker].intact !== false`, health and expectations not red, risk amber or red.
- `notesFor(subject, desk) → { lastLooked: day|null, thinking: Note|null, next: Note|null, earlier: Note[] }` — next = latest open `next` note.
- `stocksView(market, desk, today) → { value, dayMove, dayMovePct, allTime, verdictLine, lookedToday, lastRun, themes: [{ id, name, dot, reason, rows }], unsorted: [row], coming: Item[2], look: Look|null, shortlist: [{ ...item, sincePct }], positionsNote: string|null, usage: { runs, searches, tokens } }` — `row = { ticker, tier, dots, verdict, valueGbp, hint, card }`. `verdictLine` = `brief.happened[0].text` or "Nothing that changes your view today." (or "No brief yet" with no brief today). `hint` (one of): "results <Ddd>" when a results event is within 7 days, "numbers disagree with you" when disagrees, "quiet N days" when last looked ≥ 7 days ago, else null. `usage` sums `meta.runs` in the 7 days to `today`.

### Task 3: Lens arithmetic (`planner/stocks-lenses.js`)

**Files:** Create `planner/stocks-lenses.js`, `tests/stocks-lenses.test.js`.

**Interfaces (produces):** all pure, inputs are arrays of daily closes oldest-first.
- `THRESHOLDS` — exported object, each value with a one-line comment giving the reason: `trendGreen: 0.10, trendRed: -0.10, riskAmber: 1.5, riskRed: 2.5, pe: { amber: 1.2, red: 1.5 }` (P/E over its own 5-year median), `health: { grossMargin, opMarginStdMax, roicGreen, debtToEbitdaRed }` (builder picks and comments values).
- `trend(closes) → { dot, reason, value }` — 12-1 return: close 21 trading days ago over close 252 trading days ago, minus 1. Fewer than 253 closes → grey "not enough history".
- `risk(closes) → { dot, reason, drawdown, typical }` — drawdown from the 252-day high; typical = median of the rolling 252-day drawdowns over the available history; amber at `riskAmber ×`, red at `riskRed ×`.
- `rsi14(closes) → number|null` (Wilder).
- `sigma(closes) → number` — stdev of the last 60 daily returns; `moveToday(closes)` = last return.
- `priceLens({ price, epsTtm, peHistory }) → lens` and `healthLens(facts) → lens` from SEC company-facts (`us-gaap` `GrossProfit`, `Revenues`/`RevenueFromContractWithCustomerExcludingAssessedTax`, `OperatingIncomeLoss`, `EarningsPerShareDiluted`, `StockholdersEquity`, `LongTermDebt`); missing concepts → grey "accounts not available".
- Reasons are plain English, e.g. "Up 48% over 12 months", "6% off its high — normal for it", "P/E 38, above its 5-year median of 32".

- [ ] **Step 1: Write the failing tests**: a steadily rising series → trend green and reason starts "Up"; a series flat then −20% → trend red; 100 closes → trend grey; a drawdown at 2× typical → risk amber, 3× → red; `rsi14` of a monotonic rising series → 100; P/E 1.6× median → red; a facts object without `GrossProfit` → health grey.
- [ ] **Step 2:** Run `node --test tests/stocks-lenses.test.js` — FAIL.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run — PASS. Commit "Stocks: lens arithmetic, thresholds written down with reasons".

- Produces: `createStocks({ request, props, log, now, push }) → { run(): Promise<string|null> }`.
