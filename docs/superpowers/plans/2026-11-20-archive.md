# The archive: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `data.json` drops under 1 MB by leaving out records a yearly archive file already holds, while every client keeps working on the whole document.

**Architecture:** One pure module (`js/archive.js`) owns the cold rule, the cut, the pointer and the "covered" rule. `syncOnce` gains an optional archive loader: it merges the archive into the local document when the archive is new to that loader, and pushes the slim document. The planner writes the archive once a week (`planner/archive.js`); the devices, Claude's tool, the planner and the widgets all read it.

**Tech Stack:** Plain ES modules, `node --test`, GitHub Contents and Git Blobs APIs, IndexedDB on devices, Apps Script for the planner (bundled by `planner/build.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-20-archive-design.md`

## Global Constraints

- The repo is public: tests and fixtures use invented data only. Nothing personal goes in code, comments or test names.
- Nothing may be lost. A record leaves `data.json` only when the archive file named in the pointer by blob sha holds it, read back.
- Removal is deterministic: it depends only on the document and the archive named by sha, never on a clock.
- Pointer: `calendar['archive:status']` with `files: { '<year>': '<40-hex blob sha>' }`, `through: 'YYYY-MM-DD'`, `lastRun`, `lastError`, `moved`. Source `'planner'`.
- Archive files: `archive/<year>.json` in the sync repo. Each is an ordinary document (`schema: 1`) that passes `isDoc`, built with `mergeDocs`.
- The cut is `weekStart(today) - 28 days`.
- Before pushing a change to a `sw.js` SHELL file: `npm test`, then `npm run build` (planner bundle + offline release).
- No paid AI APIs; none are involved here.

## Review Focus

1. **A device whose archive download fails.** It must still apply the remote changes locally, push nothing, and say why in the header. Pinned in Task 3 (`syncOnce does not push when the named archive can't be read`).
2. **The planner's archive write lands, but the read-back fails.** The pointer keeps the old sha and nothing leaves `data.json`; the next run tries again. Pinned in Task 4.
3. **An old app copy pushes the whole document after a cut.** The next new client's sync leaves the covered records out again, and the full document is unchanged. Pinned in Task 2 (`an old full copy merged back changes nothing`) and Task 3.
4. **An edit to an archived record (an undo, a late tick).** It goes back into `data.json`, and the next weekly run moves it again. Pinned in Task 2 (`covered`) and Task 4 (`a late edit comes back and moves again`).
5. **The Claude skill used through the relay.** The blob comes back as GitHub's JSON with base64 content, not raw. `client.blob` must decode it. Pinned in Task 3.

### Task 2: `js/archive.js`, the rule

**Files:**
- Create: `js/archive.js`
- Test: `tests/archive.test.js`

**Interfaces:**
- Consumes: `mergeOne`, `mergeDocs` (Task 1); `MAPS`, `isDoc`, `stableStringify` (`js/doc.js`); `recordContent` (`js/record.js`); `addDays`, `weekStart` (`js/dates.js`).
- Produces:
  - `ARCHIVE_ID = 'archive:status'`, `ARCHIVE_DAYS = 28`.
  - `archiveCut(today: string) → string`. Returns `addDays(weekStart(today), -28)`.
  - `aboutDay(map, id, rec) → string|null`. The day a record is about, or null when it never moves. It follows the spec's table:
    - Every day it returns must be a valid `YYYY-MM-DD`.
    - Items:
      - Archived or dismissed: `archivedOn`.
      - Active `type: 'task'`: `date`.
      - Anything else: null.
    - Goals and milestones: `archivedOn` when archived or dismissed.
    - Flags: `archivedOn` when not active.
    - Logs and journal: `day`.
    - Gym: `day` for `w:`, `h:` and `back:` ids.
    - Meals: `day` when `kind === 'meal'`.
    - Game: `day` for `day:` ids.
    - Calendar:
      - `hours:`, `work:`, `eu:`, `commit:`, `closed:`, `count:` and `conflict:` ids: `day`.
      - `off:`: the first 10 characters of `end ?? start`.
      - `payslip:`: `to`.
    - Changes, workflow maps and everything else: null.
  - `archiveFiles(doc) → { [year]: sha } | null`. Read from the active pointer. Only entries whose year matches `/^\d{4}$/` and whose sha matches `/^[0-9a-f]{40}$/` count. Returns null when no entry does.
  - `covered(map, rec, archived) → boolean`. True when `archived` is a record and `stableStringify(recordContent(mergeOne(map, archived, rec))) === stableStringify(recordContent(mergeOne(map, archived, archived)))`. Merging `archived` with itself gives its normalised form.
  - `slimDoc(doc, archive) → doc`. A shallow copy of `doc` with every record left out that the archive covers. Only the archive's records are walked. A map with nothing left out keeps its own object.
  - `coldRecords(doc, archive, cut) → { years: { [year]: { [map]: { [id]: rec } } }, count: number }`. Every record whose `aboutDay` is before `cut` and that `archive` does not cover. It goes under the year of its day.
  - `yearDoc(records) → doc`. Returns `emptyDoc()` with the records filled in.
  - `createArchiveLoader({ cache = null } = {}) → { load, merged, prime }`:
    - `load(files, readBlob: (sha) → Promise<string>) → Promise<{ doc, key, fresh }>` merges every year's file. It reads each file from memory first, then from `cache.get(sha)`, then from `readBlob(sha)`. A blob it downloads is written to `cache.put(sha, text)`. It throws when a file can't be read, isn't JSON, or fails `isDoc`.
    - `key` is the `stableStringify` of the files.
    - `fresh` is `key !== the last key passed to merged()`.
    - `merged(key)` records that this archive is now in the store.
    - `prime(sha, text)` hands the loader a file it has just written and read back.
    - After a successful load, `cache.keep?.(shas)` is called with the current shas.
  - `archiveCache(backend: { get, put, del }) → { get, put, keep }`. The device cache, keyed `archive:<sha>`, with an `archive:index` list so that `keep` can delete the shas no longer named. Every call fails soft.

- [ ] **Step 1: Write the failing tests** (invented records only):
  - `archiveCut: Monday of the week less 28 days`: `archiveCut('2026-11-20') === '2026-10-19'` and `archiveCut('2026-11-16') === '2026-10-19'`.
  - `aboutDay follows the table`: one assertion per row, plus the "never moves" cases. These include an active habit, a quota, an open flag, `gym.config`, `meals['usual:x']`, `game['claim:x']`, `calendar['day:1']`, `calendar['usage:…']`, a change, and a record whose day is malformed (all null).
  - `covered`:
    - An exact copy is covered.
    - An older copy is covered.
    - A copy without stamps whose content matches a stamped archive copy is covered, and the other way round.
    - A newer edit is not covered.
    - A record the archive lacks is not covered.
    - Two same-`updated` unstamped versions are covered only when the archive's version wins `pickWinner`.
  - `slimDoc leaves out covered records only, and doesn't touch untouched maps`.
  - `an old full copy merged back after a cut changes nothing`. Set `full = mergeDocs(slim, archive)`. Assert `slimDoc(mergeDocs(slim, oldFull), archive)` stringifies equal to `slim`. Assert `mergeDocs(full, oldFull)` equals `full`, where `oldFull` has older versions of archived records.
  - `the slim file plus the archive equals the whole, record for record`. Assert `sameDoc(mergeDocs(slimDoc(full, a), a), full)` (from `js/merge.js`).
  - `coldRecords picks by the cut and the year, and skips what is covered`.
  - Loader:
    - `the loader reads each sha once, prefers its cache, and is fresh once per key`.
    - `the loader throws on an unreadable file or one that isn't a document`.
    - `prime spares a download`.
    - `archiveCache keeps only the named shas`.

### Task 3: The sync engine, devices, Claude's tool and the widgets read the archive

**Files:**
- Modify: `js/sync.js`. Add `client.blob(sha)`. `syncOnce` takes `archive`.
- Modify: `claude/session.js`. `openSession` merges the archive in, and `push` passes the loader.
- Modify: `planner/glance.js`. `handleGlance` merges the archive in.
- Modify: `js/app.js`. One loader with an IndexedDB cache (`archiveCache(idbBackend())` from `js/bigstore.js`), passed to `syncOnce`.
- Modify: `sw.js`. Add `'js/archive.js'` to SHELL.
- Test: `tests/archive-sync.test.js`, `tests/sync.test.js` (client.blob), `tests/glance.test.js` or `tests/glance-planner.test.js` (whichever builds `handleGlance` with a fake request)

**Interfaces:**
- Consumes: Task 2's `archiveFiles`, `slimDoc`, `createArchiveLoader`, `archiveCache`.
- Produces:
  - `client.blob(sha) → Promise<string>`:
    - It calls `GET /repos/<repo>/git/blobs/<sha>` with `Accept: application/vnd.github.raw+json`.
    - If the body is GitHub's blob JSON (`isBlobJson`), it decodes the base64.
    - It throws `explain(...)` on a non-OK answer.
  - `syncOnce({ store, client, archive = null, maxAttempts = 3 })`:
    1. After the merge, if `archive && archiveFiles(merged)`, it loads the archive.
    2. On a load failure, it applies `merged` locally and returns `{ ok: false, error: 'Couldn't read the archive, so nothing was sent: <why>' }`.
    3. If the load is `fresh`, it sets `merged = mergeDocs(merged, loaded.doc)`, and after `replaceDoc` it calls `archive.merged(loaded.key)`.
    4. It compares and pushes `slimDoc(merged, loaded.doc)` in place of `merged`. Without an archive it behaves exactly as before.
  - `openSession({ client, …, archive = createArchiveLoader() })`:
    - If the remote has archive files, it loads them, builds the store from `mergeDocs(remote.doc, archive.doc)` and calls `archive.merged(key)`.
    - It throws `Couldn't read the dashboard's archive: <why>` on failure.
    - `push()` calls `syncOnce({ store, client, archive })`.
  - `handleGlance`:
    - It reads each named blob raw with `request`, checks `isDoc` and merges the blobs in before `glanceOf`.
    - If an archive file can't be read, it replies `{ error: "The widgets couldn't read the dashboard's archive (GitHub <status>)" }`.

- [ ] **Step 1: Write the failing tests:**
  - `client.blob reads raw, and decodes GitHub's JSON when that's what comes back`.
  - `syncOnce with an archive pushes the slim document and keeps the whole one locally`. The fake client gains a `blobs` map and `blob(sha)`.
  - `syncOnce merges a new archive in once`. A store missing archived records gets them on the first sync. A second sync calls `blob` no more.
  - `syncOnce does not push when the named archive can't be read`. The remote's new record is still applied locally, and `puts` is unchanged.
  - `an old app's full push is slimmed again by the next new client`.
  - `openSession sees archived records, and its push leaves them out of data.json`.
  - `openSession stops when the archive can't be read`.
  - `handleGlance counts archived logs in goal totals`. Use a goal with one log in the archive and one in data.json, and assert the total includes both.
  - `handleGlance says so when the archive can't be read`.
- [ ] **Step 2: Run them and make sure they fail.**

  - Create `const archive = createArchiveLoader({ cache: archiveCache(idbBackend()) })` once.
  - Pass `archive` to `syncOnce` in `runSync`.
  - Nothing else changes, and the header shows the error as it shows any sync error.

### Task 4: The planner reads and writes the archive

**Files:**
- Create: `planner/archive.js`
- Modify: `planner/gas.js`. In `open()`, load the archive and return `archive`. Add a `save(session)` helper used at every `syncOnce` call (the inbound save, the main save, pings, nudges and `pause`). Run the weekly step before `heartbeat`.
- Modify: `tests/planner-apps.js`. `FakeRepo` gives files under `archive/` a 40-hex sha (git-style, SHA-1 of the text), and serves their blobs raw or as JSON. A `failBlob` set makes a named sha's read fail.
- Test: `tests/planner-archive.test.js`

**Interfaces:**
- Consumes: `archiveCut`, `coldRecords`, `yearDoc`, `archiveFiles`, `covered`, `ARCHIVE_ID`, `createArchiveLoader` (Task 2); `client.blob` and `syncOnce({ archive })` (Task 3).
- Produces:
  - `runArchive({ store, loader, clientFor: (path) → { get, put, blob }, readBlob: (sha) → Promise<string>, today, now: Date }) → Promise<{ ran: boolean, moved: number, error: string|null }>`. It does nothing (`ran: false`) unless one of these holds:
    - there is no pointer;
    - `pointer.through < archiveCut(today)`;
    - `pointer.lastError` is set and `lastRun` is at least an hour old.

    Otherwise it follows the spec's steps 2–5:
    - **Per year, it writes and reads back.** It sets `next = mergeDocs(got?.doc ?? emptyDoc(), yearDoc(records))` and then `sha = await put(next, got?.sha)`. Then it calls `blob(sha)` and parses the result. The year counts only if `isDoc` passes and every record written is `covered` by the read-back.
    - **It updates the pointer.** It calls `store.putCalendar(ARCHIVE_ID, { files, through, lastRun, lastError, moved }, 'planner')`:
      - `files` holds the new shas for the good years and the old shas for the others.
      - `through` is the cut only when every year succeeded; otherwise the old `through` stays.
    - It calls `loader.prime(sha, text)` for each good year.
    - It never throws. A failure becomes `lastError`, and the log gets one line.
  - In `planner/gas.js`:
    - `open()` throws `Couldn't read the dashboard's archive: <why>` when a named file can't be read, just as it throws for `data.json`.

- [ ] **Step 1: Write the failing tests** (`tests/planner-archive.test.js`, with `FakeRepo` and `appsScript`):
  - `the first run with old records writes archive/<year>.json per year, names them by sha, and data.json leaves them out`. Check that:
    - after the run, `repo.doc()` lacks the old records;
    - `repo.file('archive/2025.json')` and `repo.file('archive/2026.json')` hold them;
    - the pointer's shas are the blob shas;
    - recent records stay.
  - `nothing is lost`: `mergeDocs(repo.doc(), every archive file)` holds every original record with its content.
  - `a second run the same week writes no archive file`: the count of PUTs to `archive/` is unchanged.
  - `a failed archive write leaves the pointer alone and drops nothing`: the fake answers 500 to the PUT.
  - `a failed read-back leaves the pointer alone and drops nothing`: the `failBlob` case.
  - `a late edit to an archived record comes back into data.json and moves again the next week`.
  - `the planner's other steps see archived records`: an archived log still counts. Use `doneOn` from `planner/ticks.js` on the opened store, or the plan's done check, whichever is simplest.
  - `the run stops when the archive can't be read`: `run()` returns `'failed'` and `data.json` is not written.
