# Food (Build 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Snap a meal (photo plus an optional line, or a usual meal in one tap). Gemini estimates
protein and kcal as ranges. A Fuel tile shows protein against 180 g and the week's kcal average,
and Claude can read every meal and its photo and correct a big miss.

**Architecture:** The logic is pure in `js/food.js`: prompt, reply parsing, portions, slots, totals,
usual meals, and which meals still need work. Meals are records in a new `meals` map in `data.json`,
merged like every other map. Photos are shrunk on the device and kept in IndexedDB until they've been
estimated and uploaded to `dashboard-sync/photos/YYYY/MM/<id>.jpg` (`js/photos.js`). `askGemini`
learns to send one image. The UI is a snap sheet (`js/ui/snap.js`), a Fuel tile, and meal markers on
the Daylight timeline. Claude gains `food` and `photo` reads, a `meal` op, a catch-up line and a
`food` playbook.

**Tech Stack:** Plain ES modules, Node 24 `node --test`, the free Gemini tier (Flash-Lite first,
then Flash), the GitHub contents API, IndexedDB, canvas.

**Spec:** `docs/superpowers/specs/2026-10-18-daylight-health-design.md`, "Build 3: Food".

## Global Constraints

- No paid AI. Gemini gets the photo, the line and the time, nothing else. Watch data never goes to
  Gemini.
- Protein is the hero number. Calories are judged only as a weekly average against `maintenanceKcal`,
  never as a daily target, and never shown in red.
- Portions: lighter 0.75, about right 1, bigger 1.3, scaling the mid values.
- Slots: breakfast before 11:00, lunch 11:00–15:00, dinner 17:00–21:30, snack otherwise (local time).
- Meal markers on the timeline at 08:00, 12:30 and 19:00, each only while its slot has no meal.
- Photos: 768 px longest side for Gemini, a 480 px JPEG (quality 0.7) kept, under `photos/YYYY/MM/<id>.jpg`.
- `fuel:settings` is `{ kind: 'settings', protein: 180, maintenanceKcal: null }`. With no
  `maintenanceKcal`, show the average and no verdict. "About maintenance" means within ±10%.
- Meals are archived, never deleted. A `correction` from Claude overrides `final` in every total.
- Offline or a Gemini failure: the meal is kept as `pending` and estimated later. Nothing is lost.
- Every `sw.js` shell change ships with `npm run build`, and every push follows `npm test`.

## Review Focus

1. **Offline at lunch.** The photo waits, the Fuel tile says "1 meal waiting", and it's estimated and
   uploaded once online, even after a reload (Task 4).
2. **Gemini replies with nonsense or partial JSON.** The meal is kept as `failed`, with the words and
   photo intact. It's retried on the next pass, at most 3 times, then left for Claude (Task 1, Task 4).
3. **Two devices.** A meal from the phone and one from the laptop on the same day both survive the
   merge and both count (Task 2).
4. **A usual meal with no photo** logs exactly, with no Gemini call (Tasks 1 and 5).
5. **Claude corrects a meal.** Totals follow the correction everywhere, and the tile marks it (Tasks 1
   and 6).

### Task 1: Food logic (`js/food.js`)

**Files:** Create `js/food.js`, `tests/food.test.js`. Modify `sw.js` (shell).

**Interfaces (Produces):**
- `PORTIONS = { lighter: 0.75, right: 1, bigger: 1.3 }`
- `slotFor(date: Date) -> 'breakfast'|'lunch'|'dinner'|'snack'`
- `MEAL_SYSTEM: string`: the instruction. Estimate protein (g) and kcal for the meal in the photo
  and/or words. Reply only with JSON
  `{ "name": string, "items": [{ "name", "protein", "kcal" }], "protein": { "low", "mid", "high" }, "kcal": { "low", "mid", "high" } }`.
  Use typical UK portions unless the words say otherwise.
- `mealPrompt({ text, at: Date, hasPhoto: boolean }) -> string`
- `parseEstimate(data) -> { name, items, protein: {low, mid, high}, kcal: {low, mid, high} }`:
  throws `Error('Gemini’s estimate didn’t make sense')` unless the numbers are finite, ≥ 0,
  low ≤ mid ≤ high, and the name is a non-empty string. Rounds protein to whole grams and kcal to
  the nearest 10.
- `finalFor(estimate, portion) -> { protein, kcal }`: mid × PORTIONS[portion], rounded as above.
- `mealValue(meal) -> { protein, kcal } | null`: `correction` if present, else `final`, else null.
- `mealsOn(doc, day) -> meal[]`: active meals of that day, by `at`.
- `dayProtein(doc, day) -> number`
- `weekKcal(doc, today) -> { average: number|null, days: number }`: the mean over the last 7 days that
  have at least one valued meal. `average` is null with no such days.
- `fuelSettings(doc) -> { protein: 180, maintenanceKcal: number|null }`
- `maintenanceVerdict(average, maintenanceKcal) -> 'about maintenance'|'above maintenance'|'below maintenance'|null`
- `usualMeals(doc) -> [{ id, name, protein, kcal, uses }]`, by uses descending.
- `mealWork(doc, localIds: Set<string>) -> { estimate: meal[], upload: meal[] }`: meals this device
  holds a photo for (`localIds`). `estimate` is `status` pending, or failed with `tries < 3`.
  `upload` is `photoState === 'local'`.
- `MAX_TRIES = 3`

import { test } from 'node:test';
import assert from 'node:assert/strict';
import { slotFor, parseEstimate, finalFor, mealValue, dayProtein, weekKcal, maintenanceVerdict, usualMeals, mealWork, mealPrompt, MEAL_SYSTEM } from '../js/food.js';
import { fixture } from './helpers.js';

const est = { name: 'Chicken wrap and crisps', items: [{ name: 'Wrap', protein: 40, kcal: 560 }], protein: { low: 38, mid: 46, high: 54 }, kcal: { low: 650, mid: 780, high: 900 } };
const meal = (id, day, extra) => ({ id, kind: 'meal', day, at: `${day}T12:30:00.000Z`, status: 'estimated', estimate: est, portion: 'right', final: { protein: 46, kcal: 780 }, ...extra });

test('slots follow the clock', () => {
  assert.equal(slotFor(new Date(2026, 9, 20, 7, 20)), 'breakfast');
  assert.equal(slotFor(new Date(2026, 9, 20, 12, 34)), 'lunch');
  assert.equal(slotFor(new Date(2026, 9, 20, 16, 0)), 'snack');
  assert.equal(slotFor(new Date(2026, 9, 20, 19, 0)), 'dinner');
  assert.equal(slotFor(new Date(2026, 9, 20, 22, 0)), 'snack');
});

test('a sound estimate is kept and rounded; nonsense or a partial reply is refused', () => {
  assert.deepEqual(parseEstimate({ ...est, protein: { low: 37.6, mid: 46.2, high: 54 }, kcal: { low: 648, mid: 783, high: 901 } }).kcal, { low: 650, mid: 780, high: 900 });
  for (const bad of [{}, { ...est, name: '' }, { ...est, protein: { low: 50, mid: 40, high: 60 } }, { ...est, kcal: { low: -1, mid: 1, high: 2 } }, 'text']) {
    assert.throws(() => parseEstimate(bad), /didn’t make sense/);
  }
});

test('portions scale the middle of the range', () => {
  assert.deepEqual(finalFor(est, 'lighter'), { protein: 35, kcal: 590 });
  assert.deepEqual(finalFor(est, 'bigger'), { protein: 60, kcal: 1010 });
});

test("Claude's correction wins in every total", () => {
  const doc = fixture();
  doc.meals = { a: meal('a', '2026-10-20'), b: meal('b', '2026-10-20', { correction: { by: 'claude', protein: 20, kcal: 900, why: 'big pasta' } }) };
  assert.deepEqual(mealValue(doc.meals.b), { protein: 20, kcal: 900 });
  assert.equal(dayProtein(doc, '2026-10-20'), 66);
});

test("the week's kcal is a mean over days with meals, and the verdict is ±10%", () => {
  const doc = fixture();
  doc.meals = { a: meal('a', '2026-10-19'), b: meal('b', '2026-10-20'), c: meal('c', '2026-10-20') };
  assert.deepEqual(weekKcal(doc, '2026-10-20'), { average: 1170, days: 2 });
  assert.deepEqual(weekKcal(fixture(), '2026-10-20'), { average: null, days: 0 });
  assert.equal(maintenanceVerdict(3050, 3000), 'about maintenance');
  assert.equal(maintenanceVerdict(3400, 3000), 'above maintenance');
  assert.equal(maintenanceVerdict(3050, null), null);
});

test('usual meals by use; work only for meals this device holds a photo for', () => {
  const doc = fixture();
  doc.meals = {
    u1: { id: 'u1', kind: 'usual', name: 'Whey shake', protein: 25, kcal: 120, uses: 9, status: 'active' },
    u2: { id: 'u2', kind: 'usual', name: 'Usual breakfast', protein: 42, kcal: 610, uses: 14, status: 'active' },
    p: meal('p', '2026-10-20', { status: 'pending', photoState: 'local' }),
    f: meal('f', '2026-10-20', { status: 'failed', tries: 3, photoState: 'uploaded' }),
    g: meal('g', '2026-10-20', { status: 'failed', tries: 1, photoState: 'local' }),
  };
  assert.deepEqual(usualMeals(doc).map((u) => u.name), ['Usual breakfast', 'Whey shake']);
  const work = mealWork(doc, new Set(['p', 'g']));
  assert.deepEqual(work.estimate.map((m) => m.id), ['p', 'g']);
  assert.deepEqual(work.upload.map((m) => m.id), ['p', 'g']);
  assert.deepEqual(mealWork(doc, new Set()).estimate, []);
});

test('the prompt carries the words and the time, and the system asks for JSON only', () => {
  const p = mealPrompt({ text: 'chicken wrap, a big one', at: new Date(2026, 9, 20, 12, 34), hasPhoto: true });
  assert.match(p, /chicken wrap, a big one/);
  assert.match(p, /12:34/);
  assert.match(MEAL_SYSTEM, /JSON/);
});

### Task 4: Photos: shrink, keep, estimate, upload (`js/photos.js`)

**Files:** Create `js/photos.js`. Test: `tests/photos.test.js`. Modify `js/app.js` (run the meal pass
on save, on `online`, after each sync, at boot) and `sw.js`.

**Interfaces (Produces):**
- `photoPath(id, at: Date) -> 'photos/YYYY/MM/<id-without-prefix>.jpg'`
- `uploadPhoto({ token, repo, path, base64, fetch }) -> Promise<void>`: GitHub `PUT /repos/{repo}/contents/{path}`
  with `{ message: 'Meal photo', content: base64 }`. A 422 ("already exists") counts as done.
  Anything else throws `Error('Couldn’t upload the photo (<status>)')`.
- `shrink(file, maxSide, quality) -> Promise<{ base64, width, height }>`: browser only (createImageBitmap
  plus canvas). Not unit-tested.
- `localPhotos`: IndexedDB `dash_photos`, store `photos` keyed by meal id, holding `{ big, small }`
  base64. `put(id, value)`, `get(id)`, `del(id)`, `ids() -> Set`. Browser only; every call is wrapped
  in try/catch and falls back to an empty Set.
- `runMealPass(ctx) -> Promise<{ estimated, uploaded, failed }>`:
  - `mealWork(doc, await localPhotos.ids())`;
  - each estimate calls `ctx.gemini.ask({ system: MEAL_SYSTEM, prompt, image })`, then `parseEstimate`,
    then `updateMeal({ status: 'estimated', estimate, final: finalFor(estimate, meal.portion ?? 'right') })`.
    A failure sets `status: 'failed', tries + 1`, and no key keeps it `pending`;
  - each upload (with sync set up) does `uploadPhoto` on the small JPEG, then
    `updateMeal({ photo: path, photoState: 'uploaded' })`;
  - once estimated and uploaded, it deletes the local copy;
  - offline it does nothing. Never two passes at once.
  - Words-only pending meals (no photo) are estimated from the words alone by whichever device runs a pass first; a second estimate of the same meal is harmless (it only rewrites the estimate).
- [ ] **Step 1: Failing tests.**
  - `photoPath('meal:abc', new Date(2026, 9, 20))` is `'photos/2026/10/abc.jpg'`.
  - `uploadPhoto` sends PUT with auth and base64 content to the right URL, accepts 201 and 422, and
    throws on 500.
  - `runMealPass` with a fake `localPhotos` (injected) and a fake Gemini estimates a pending meal and
    uploads it. A nonsense reply sets `failed` with `tries: 1`. With no keys it stays `pending`.
    Offline (`navigator.onLine` false, injected) it does nothing. Two calls at once run once.
- [ ] **Step 2: Run them.** Expected: FAIL.
- [ ] **Step 3: Implement it.** `runMealPass` takes `{ ctx, photos = localPhotos, online = () => navigator.onLine, sync }` so tests can inject.
