# Daylight (Build 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second screen, "Daylight", that shows everything the current dashboard does as the sky,
the timeline and the tiles, built beside the classic screen and switched with a setting.

**Architecture:** All logic goes in small pure modules with Node tests: `js/sky.js`,
`js/timeline.js`, `js/header.js`, `js/tiles.js` and `js/needs.js`. The drawing modules are thin:
`js/ui/sky.js`, `js/ui/timeline.js`, `js/ui/tiles.js` and `js/ui/needs.js`. They reuse the existing
row, check-in, note and widget renderers, restyled by `styles/daylight.css`, which is scoped to
`html[data-screen="daylight"]`. `js/app.js` picks the renderer from `settings.screen` or `?daylight`.
The classic screen is untouched apart from small exports.

**Tech Stack:** Plain ES modules, no framework, no runtime dependencies. Node 24 `node --test`.
Playwright via `npm run test:browser`. Self-hosted woff2 fonts (SIL OFL).

**Spec:** `docs/superpowers/specs/2026-10-18-daylight-health-design.md`, the "Build 1: Daylight"
section, plus "Rules for the screen". Mockups: canvas https://claude.ai/artifact/P5eXz4WSve5YXvyybkzYFb,
row "Daylight v2".

## Global Constraints

- No framework and no runtime dependencies. `h()` from `js/ui/dom.js` builds the DOM.
- Each number in one place. Depth behind a tile's big view. Nothing is added in the app.
- Ticking happens only in the timeline. Ticked rows stay visible (faded, gold tick).
- "Added by" words are hover text only; the row shows the mark (`sourceMark` from `js/ui/sources.js`).
- Area colours: Body coral `#FF8A65` (ink text), Fuel green `#24785A` (white text), Hebrew indigo
  `#3F3A9E` (white text), Needs you yellow `#FFD36B` (ink text). Ink `#1D1A2B`, ground `#FFF8EF`.
  Gold `#E2A400` means "you did it" and nothing else.
- Fonts: Bricolage Grotesque (display), Figtree (text), Rubik (Hebrew), self-hosted under `fonts/`.
  No request to fonts.googleapis.com.
- No gradient washes: the sky is bands of flat colour. Icons are inline stroke SVG. No emoji in the
  interface, except the glyphs the classic rows already use (★, ≡, the 📌 pin) until a later pass.
- Contrast: text 4.5:1, text 24px and up 3:1, in both the day and night token sets.
- All motion is off under `@media (prefers-reduced-motion: reduce)`.
- The Look setting keeps `auto | paper | night` and the `<head>` script's rule (night from
  `checkinHour` until `dayStartHour`). `tests/look.test.js` must keep passing unchanged.
- The classic screen keeps working, and every existing test passes, after every task.
- Every commit that touches a `sw.js` shell file runs `npm run build` and includes `release.json`.
  Before any push: `npm run build && npm test`.
- Copy is British English, in the house voice: short, plain, and the user is "you".

## Review Focus

1. **Typing while a sync lands.** A half-typed check-in or Tell Claude note in Daylight must survive a
   re-render. `typing()` must look inside `#timeline, #tiles, #dl-sky`, and the timeline must restore
   focus with `keptFocus`/`restoreFocus` (Task 7 has the test).
2. **No calendar data.** If the planner has never run or the day has no blocks, every row goes under
   "Any time today", the sky has no dots, and an empty day shows "Nothing on today. Tell Claude what
   you want to get done." (Task 2 tests the model; Task 7 the empty text.)
3. **Before sunrise and after sunset.** At 05:30 or 23:00 the sun isn't drawn on the arc
   (`up: false`), the moon shows, and blocks outside daylight get no dot (Task 1).
4. **Overlapping blocks.** Two tasks in one block, or a task and a commitment at the same minute: a
   stable order (by start; rows before commitments; then the existing `todayRows` order) and no row
   lost (Task 2).
5. **Away from London and after midnight.** On a Salzburg phone (`Europe/Vienna`) the sky uses
   Salzburg's sun. At 01:00, still the previous logical day, the now line sits after every entry
   (Tasks 1 and 2).

### Task 1: The sky's maths

**Files:**
- Create: `js/sky.js`
- Test: `tests/sky.test.js`

**Interfaces:**
- Produces:
  - `PLACES: { london: { name: 'London', lat: 51.5074, lon: -0.1278 }, salzburg: { name: 'Salzburg', lat: 47.8095, lon: 13.055 } }`
  - `placeFor(timeZone: string, setting = 'auto') -> { key, name, lat, lon }`: a setting of `london`
    or `salzburg` wins. Under `auto`, `Europe/Vienna` gives Salzburg and anything else London.
  - `sunTimes(day: 'YYYY-MM-DD', place) -> { sunrise: Date, noon: Date, sunset: Date }`: the NOAA
    solar position algorithm (solar declination and equation of time, zenith 90.833°), worked in UTC
    from the place's longitude, so it doesn't depend on the machine's time zone.
  - `skyPhase(now: Date, times) -> 'night'|'dawn'|'morning'|'midday'|'afternoon'|'golden'|'dusk'`. The
    boundaries are: dawn from sunrise − 45 min to sunrise + 30; morning until noon − 90; midday until
    noon + 90; afternoon until sunset − 75; golden until sunset; dusk until sunset + 45; night
    otherwise.
  - `arcPoint(t: number) -> { x, y }`: on a quadratic Bézier in a unit box, P0 (0.0417, 0.933),
    P1 (0.5, −0.4), P2 (0.9583, 0.933). Clamps `t` to 0–1.
  - `sunAt(now, times) -> { up: boolean, t: number, x, y }`, where `t = (now − sunrise) / (sunset − sunrise)`
    and `up` is true only between sunrise and sunset.
  - `blockDots(blocks: [{ id, title, start: iso, done: boolean, area: string|null }], times) -> [{ id, title, done, area, x, y }]`:
    only blocks starting between sunrise and sunset.

```js
// tests/sky.test.js
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { PLACES, placeFor, sunTimes, skyPhase, arcPoint, sunAt, blockDots } from '../js/sky.js';

const near = (actual, iso, minutes) => assert.ok(Math.abs(actual - Date.parse(iso)) <= minutes * 60000, `${actual.toISOString()} vs ${iso}`);

test('London on 21 June and 20 October, within five minutes of the published times', () => {
  const june = sunTimes('2026-06-21', PLACES.london);
  near(june.sunrise, '2026-06-21T03:43:00Z', 5);
  near(june.sunset, '2026-06-21T20:21:00Z', 5);
  const oct = sunTimes('2026-10-20', PLACES.london);
  near(oct.sunrise, '2026-10-20T06:29:00Z', 5);
  near(oct.sunset, '2026-10-20T16:57:00Z', 5);
});

test('Salzburg on 20 October rises earlier than London', () => {
  const s = sunTimes('2026-10-20', PLACES.salzburg);
  near(s.sunrise, '2026-10-20T05:24:00Z', 8);
  near(s.sunset, '2026-10-20T16:03:00Z', 8);
});

test('the place follows the time zone unless the setting pins it', () => {
  assert.equal(placeFor('Europe/Vienna').key, 'salzburg');
  assert.equal(placeFor('Europe/London').key, 'london');
  assert.equal(placeFor('America/New_York').key, 'london');
  assert.equal(placeFor('Europe/Vienna', 'london').key, 'london');
});

test('phases across a day', () => {
  const t = sunTimes('2026-10-20', PLACES.london);
  const at = (ms) => skyPhase(new Date(ms), t);
  assert.equal(at(t.sunrise - 60 * 60000), 'night');
  assert.equal(at(t.sunrise - 10 * 60000), 'dawn');
  assert.equal(at(t.sunrise + 60 * 60000), 'morning');
  assert.equal(at(+t.noon), 'midday');
  assert.equal(at(t.sunset - 120 * 60000), 'afternoon');
  assert.equal(at(t.sunset - 30 * 60000), 'golden');
  assert.equal(at(t.sunset + 20 * 60000), 'dusk');
  assert.equal(at(t.sunset + 90 * 60000), 'night');
});

test('the arc runs from the left horizon over the top to the right', () => {
  assert.deepEqual(arcPoint(0), { x: 0.0417, y: 0.933 });
  assert.ok(Math.abs(arcPoint(0.5).x - 0.5) < 1e-9);
  assert.ok(arcPoint(0.5).y < arcPoint(0.1).y);
  assert.deepEqual(arcPoint(1.4), arcPoint(1));
});

test('the sun is only up between sunrise and sunset', () => {
  const t = sunTimes('2026-10-20', PLACES.london);
  assert.equal(sunAt(new Date(t.sunrise - 60000), t).up, false);
  assert.equal(sunAt(new Date(+t.noon), t).up, true);
  assert.equal(sunAt(new Date(t.sunset + 60000), t).up, false);
});

test('only blocks in daylight get a dot', () => {
  const t = sunTimes('2026-10-20', PLACES.london);
  const dots = blockDots([
    { id: 'a', title: 'Hebrew', start: '2026-10-20T08:00:00Z', done: true, area: 'Hebrew' },
    { id: 'b', title: 'Read', start: '2026-10-20T20:00:00Z', done: false, area: null },
  ], t);
  assert.deepEqual(dots.map((d) => [d.id, d.done]), [['a', true]]);
  assert.ok(dots[0].x > 0.0417 && dots[0].x < 0.5);
});
```

### Task 2: The timeline's model

**Files:**
- Create: `js/timeline.js`
- Test: `tests/timeline.test.js`

**Interfaces:**
- Consumes: `todaySlots(doc, today)` and `clockLabel(iso)` from `js/calendar.js`; `dayRecord(doc, day)`
  from `js/calendar.js`; `scheduleView(doc, today).commitments` and `localDate(iso)` from
  `js/plan-state.js`; `listRows(rows)` from `js/ui/today.js`; `todayRows(doc, today)` from
  `js/schedule.js`; `addDays` from `js/dates.js`.
- Produces:
  - `timelineModel({ rows, slots: Map, commitments: [{ title, calendar, start, end, allDay? }], today, now: Date }) -> { timed: Entry[], anytime: Row[], nowIndex: number }`,
    where `Entry = { kind: 'row', start, end, row } | { kind: 'commitment', start, end, title, calendar }`.
    - Rows with a slot are timed. Suggested rows and rows without a slot go to `anytime`, in their
      given order.
    - Commitments are kept only when `localDate(start) === today` and they aren't `allDay`.
    - `timed` is sorted by start, then rows before commitments, then the given order.
    - `nowIndex` is the index of the first entry whose `start` is after `now` (`timed.length` when
      none is).
  - `tomorrowLine(doc, today) -> string|null`: tomorrow's blocks from `dayRecord(doc, addDays(today, 1)).blocks`
    as `"<title> <HH:MM>"` joined with `" · "`, a rough block's time prefixed with `~`. `null` when
    there are none.

### Task 4: Needs you, in plain words

**Files:**
- Create: `js/needs.js`
- Modify: `js/ui/agenda.js` (its `needsYou` filter moves to `js/needs.js` and is imported back)
- Test: `tests/needs.test.js`

**Interfaces:**
- Consumes: `scheduleView(doc, today)` (`js/plan-state.js`); `shortWeekday`, `addDays` (`js/dates.js`).
- Produces:
  - `needsEntries(doc, today) -> Entry[]`: exactly the entries today's Upcoming calls "needs you" (a
    conflict, a `scheduleHold` task, or an unscheduled task after today within 14 days), in
    `scheduleView` order.
  - `needsCopy(entry, doc) -> { text: string, choices: [{ choice: 'calendar'|'dashboard', label: string }] }`:
    - A conflict with `changes.time` and an `item.time`: "You moved <title> to <changes.time> in
      Google Calendar, but the dashboard still has <item.time>." Choices: `Keep <changes.time>`
      (calendar) and `Back to <item.time>` (dashboard).
    - A conflict with `calendarValid === false`: "The Calendar edit to <title> isn't a time the
      dashboard can use." Only the dashboard choice: `Keep the dashboard's`.
    - Any other conflict: "<title> was changed in Google Calendar and here." Choices: `Keep
      Calendar's` and `Keep the dashboard's`.
    - `scheduleHold`: "<title> was taken out of Google Calendar. Tell Claude when to do it." No
      choices.
    - Unscheduled: "<title> · <Weekday>: waiting for a calendar slot." No choices.
